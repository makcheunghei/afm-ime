# AFM速成：資料、操作及驗證

AFM速成是 AFM輸入法的新增系統輸入來源。AFM拼音仍使用原有拼音引擎；兩者共用 App、設定中心及 Liquid Glass 視窗框架。

## 預設與可選功能

預設按靜態 Windows 原生資料排序，每頁九個候選。完整字集、速成個人學習、速成 AI 推薦、推薦雲端及翻譯雲端均預設關閉，可在設定中心「輸入設定 → AFM速成」手動開啟。

完整字集保留預設字序在前，另外追加原生擴展字及既有 CIN 字表中未出現的字。個人學習以速成碼分開記錄，使用 `AFMQuickUserCounts`，不讀寫拼音學習資料；關閉時不記錄新選字。

AI 只推薦現有候選，不生成新字；第一候選保持原位，推薦移至第二位並標記 ✦。導航及翻頁操作會鎖定本次候選次序。過期、取消或不同模式的結果會丟棄。速成雲端開關與拼音雲端開關分開，開啟後共用模型頁的提供商設定，傳送速成碼、候選及光標前的一段文字；雲端失敗時沿用本機／純查表後備。

## 按鍵

| 情況 | 操作與結果 |
|---|---|
| 一碼（字碼未全） | 先顯示預覽；空白立即確認目前字，例如 O → 空白 → 人、M → 空白 → 一 |
| 雙碼 | 自動打開候選窗 |
| 第三個字母 | 收起中文候選，保留完整英文原文及大小寫，不自動提交中文 |
| 雙碼（完整字碼） | 空白循環跳至下一頁；只有一頁時不翻頁也不確認；1–9 選中文，Enter 輸出原英文 |
| 翻頁 | 雙碼的空白／右方向鍵／Page Down 向後，左方向鍵／Page Up 向前；末頁與首頁循環 |
| 導航 | 上／下移動當頁選項；左／右一律翻頁，末頁與首頁循環 |
| 候選外觀 | 可選直排或橫排，每頁最多九項；頂部只顯示目前頁／總頁數，沒有展開或翻頁按鈕；Tab 交回應用程式 |
| 取消組碼 | 有候選時 Backspace 逐字刪碼，Esc 取消組字 |
| 無候選的英文 | 空白／ASCII 標點確認原文並輸出分隔符；Delete／向前刪除第一下確認原文，下一下才交給應用刪除 |
| 聯想窗 | 1–9 直接選當頁續文，與字碼選字相同（保留 Shift＋數字）；提交後關窗，不再連鎖開聯想 |
| 聯想窗的空格 | 關窗並插入空格 |
| 聯想窗的無對應數字／Enter／Backspace | 關窗並將原鍵交回應用程式；速成數字及標點固定半形 |
| 組字中 Control＋F | 翻譯目前高亮候選；沒有中文候選時翻譯原英文。無組字或只有聯想時交回應用 |
| 翻譯中的 1／點選 | 提交已完成的譯文並關窗，不開聯想、不學習 |
| 翻譯中的 Space／2–9 | 不提交、不翻頁，也不選取原來隱藏的候選 |
| 翻譯中的 Enter | 提交原英文；Esc／再次 Control＋F 返回原候選頁 |
| 翻譯中的其他輸入 | 字母、刪除、方向鍵及標點先退出翻譯，再按原速成規則處理 |

在「輸入設定 → AFM速成 → 外觀 → 候選排列」選擇直排或橫排，預設直排。中文字及聯想採用相同排列；切換只重排畫面，保留目前頁碼、高亮、翻譯及 AI 請求。橫排仍以左右鍵／雙碼空白翻頁，上下鍵移動選中項。長候選會按可用螢幕寬度縮短顯示，懸停可查看全文，設定預覽同步切換。

候選背景沿用原生標準玻璃材質，由系統管理透明度；macOS 27 跟隨系統外觀／輔助使用設定，macOS 26 使用預設效果。部署目標為 macOS 26；本機 AI 沿用系統可用模型，雲端模型需要 macOS 27。macOS 26 的實機執行仍待驗收。

本機 Shift 中英切換及共用快捷鍵沿用原專案。相容的 Shift＋數字選聯想亦識別 macOS 數字鍵碼，可處理 AppKit 將 Shift＋1 傳成 `!` 的事件。

## 翻譯與模型設定

行內翻譯和設定中心翻譯頁共用速成專用提示詞；中文譯英文，外文譯香港繁體中文，方向判斷包括擴展漢字。主動翻譯不要求開啟自動候選推薦。

「雲端翻譯」預設關閉，與拼音雲端及速成推薦雲端分開；開啟後使用已配置的服務商，只發送所選原文，不附帶光標前文。macOS 26 使用本機模型；macOS 27 可啟用雲端，失敗回落本機。所有模型都不可用時保留原碼，失敗訊息不會成為可提交候選。改字、失焦、切換來源或修改模型設定後，過期回覆不能復活候選窗。

設定中心的模式選擇只切換所管理的內容，不切換系統輸入來源。兩種模式的提示詞草稿、搜尋和頁碼分開；「套用」及「恢復預設」只作用於目前模式。固定透鏡等拼音專用實驗不影響速成候選窗。

## 詞庫及個人選字記錄

「詞庫 → AFM速成」可查看字碼或聯想。字碼表列出字碼、字根、候選及原始位置，支援英文字碼前綴及中文字搜尋；聯想可按前字或續文搜尋。每頁 100 條，查看完整字集不會修改實際輸入開關；個人學習和 AI 亦不改動表格中的原始次序。

「個人詞語 → AFM速成」管理 `AFMQuickUserCounts` 的選字次數，支援搜尋、刪除、清空及 JSON 匯入。記錄讀改寫使用共用跨程序鎖；新增選字、刪除及匯入不會互相覆蓋。更新記錄於下次組字生效，不在選字途中改位；學習關閉時仍以 Windows 原始排序輸入。

匯入格式如下，只能調整既有字碼與候選的選取次數：

```json
{
  "version": 1,
  "mode": "quick",
  "selections": [
    { "code": "aa", "text": "晶", "count": 12 },
    { "code": "of", "text": "你", "count": 30 }
  ]
}
```

字碼必須是 1–2 個小寫英文字母，候選須存在 Windows 或完整字集，次數須為正整數。重複記錄取較大次數；無效項目略過並回報數量，錯誤模式或版本整份拒絕。匯入及管理不會開啟學習、不修改拼音資料，也不新增自訂短語。

剪貼簿在組字時仍讓數字鍵選候選；點選剪貼簿項目會先確認英文原碼，再插入文字。只有聯想窗時先關窗，不自動選聯想。Control＋`;` 保留給系統表情與符號，不能錄製為其他功能的快捷鍵。

## 資料編譯

現代 Windows 速成實際使用 `C:\Windows\InputMethod\CHT\` 的下列三個檔案，而非早期提取的 IMD 二元模型：

| 檔案 | SHA-256 |
|---|---|
| ChtQuick.lex | `48c3e8455940ff50ac71fbf5ed6af1ae6a47c320d09effc470d9885989dee266` |
| ChtQuick.spd | `004f164367b16b6bf5fa8af326583769b71905e9e8c2f8b22867c64b2c781d3d` |
| ChtQuickExt.lex | `31ff9adcd92990a37dd25fbd7ca3837d06fc8e612a1d21dcb4977b6129e45be8` |

將檔案放在 `quickime/`，或本次實測的 `quickime/windows-reference/2026-10-14/modern-system/`，即可自動找到資料。可明確指定位置：

```sh
python3 scripts/build_quick.py \
  --source quickime/windows-reference/2026-10-14/modern-system \
  --cin quickime/microsoft-quick.cin \
  --output Data/quick.json
```

編譯器驗證二進制邊界及參考案例，去除重複項目，以原生分數排序並保留同分字的穩定次序。聯想直接從原生詞語記錄切出「前文 → 續文」，沒有使用舊 IMD 聯想模型或 Windows 個人學習檔案。CIN 只用於補齊完整字集，並保留 U+3000 全形空格。生成檔案包含來源 SHA-256、篩選政策及有限驗證範圍。

本次生成數量：668 個字碼、23,442 個預設候選項、59,414 個完整字集候選項、18,322 個聯想前文及 61,397 個聯想續文。既有 CIN 的 59,399 組字碼對應全部保留在完整字集。

原生資料、Windows 實測畫面及生成詞庫留在本地，未納入 Git。`scripts/package.sh` 要求有效的 `Data/quick.json`，缺少時會嘗試從本地原始檔案生成；缺少必要來源則停止打包。

## 已驗證範圍與限制

2026-10-14 在使用者的 Windows 11 Pro 25H2、build 26200.9457，日常微軟速成設定上完成 40 個 GUI 對照記錄。樣本碼 `aa` 的完整兩頁為：

```text
1：昌 晶 暑 間 暗 曙 昍 暙 闍
2：閶 閽 闇 晿 暏 彞 龧 𣊫 𣊭
```

以下六組聯想次序與 Windows 畫面相符；九項列表表示已核對首頁，其餘為完整可見列表：

| 已提交文字 | Windows／編譯後的續文 |
|---|---|
| 你 | 們、我、老、等、死我活、推我讓 |
| 晶 | 片、瑩剔透、瑩、體、亮、狀體、粒 |
| 香 | 港、水、煙、蕉、味、腸、菸、包、菇 |
| 港 | 務局、口、都、澳、警、市、警所、幣、務 |
| 好 | 像、處、幾、奇、手、轉、評、不容易、看 |
| 暑 | 假、期、氣、熱、氣逼人 |

這些是抽樣結果。預設字集篩選、同分排序、所有字碼及其他聯想尚未逐一與 Windows 比對；完整字集更不能視為 Windows 預設候選序。按鍵中未充分核對的邊界情況，例如字碼窗的 `0` 鍵，仍需補充實測。

`scripts/test.sh --background` 執行不顯示視窗的 Swift Testing，涵蓋按鍵、翻譯取消及雲端權限隔離、資料查詢、個人記錄匯入與並行修改。模型回覆及偏好資料在測試中隔離，不呼叫真實雲端。省略 `--background` 亦會執行顯示候選視窗的測試，應在不使用電腦時進行。打包後再執行：

```sh
"build/AFM輸入法.app/Contents/MacOS/AFMInput" --check-quick
codesign --verify --deep --strict "build/AFM輸入法.app"
```

`--check-quick` 驗證實際包內資源、IMK controller 類別、Windows 參考字序、六組聯想及狀態機整合，不修改系統輸入來源。這些測試不能代替安裝後在各個 macOS 客戶端的真實打字測試。

2026.10.16.5 的背景驗證：120 項 Swift Testing 通過，包含兩個獨立程序同時記錄選字、主程序匯入及刪除的整合測試；打包後的 `--check-quick` 亦通過。翻譯測試使用假模型回覆，未發送真實雲端請求。四項會顯示候選窗的測試及本版本安裝後的實際打字／畫面驗收，留待可中斷電腦使用時進行。


## 擴展字顯示修正（2026.10.25.1）

開啟完整字集後，`ap（日心）` 第 2 頁後的 `𢘇`、`𢙶`、`𢛝` 等字，在部分 macOS 字型組合會落到 CoreText 的 LastResort 佔位字型。字碼及原始 Unicode 並未損壞。

AFM 內附未修改的 HanaMinB 後備字型，只補系統缺少的字形，涵蓋候選、預覽、速成詞庫及個人詞語表格；字型只在 AFM 程序內登記。常用字型、候選次序與提交的 Unicode 原文保持原樣。

回歸測試檢查整份速成／聯想資料的 58,206 個不同 Unicode 字元，一般及選中粗體均不得使用 LastResort 或缺失 glyph；另以離屏影像驗證 `ap` 第 2、3 頁的直排及橫排。打包後 `--check-quick` 同時檢查 `ap` 字形，可在專案外的工作目錄執行，避免誤用開發資料夾的後備字型。
